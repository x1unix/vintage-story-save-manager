# Requests for change

This directory holds the original product requirements and proposals for later functionality, improvements, and behavior changes.

Browse the numbered files in this directory for individual RFCs. Keep each RFC's status and tasks in its own document; this README does not maintain an entry list.

Create new proposals as `NNNN-short-title.md` using the next available number. Include status, motivation, requirements, design and safety considerations, implementation tasks, and verification/acceptance criteria. Use statuses such as Draft, Accepted, Implemented, Rejected, or Superseded; link replacement RFCs when superseding an earlier decision.

Record the proposal before implementation, honor decisions already approved in the conversation, and update tasks and status as work progresses. Keep the original requirements as the baseline; subsequent accepted RFCs extend or explicitly supersede earlier requirements. Update the root README and design document when behavior is implemented so planned features are not presented as available.
